# Product interface direction

Use V9.2 as the project-workspace and visual starting point, and V9.3 as the
business-reading and interaction refinement. Do not copy the V9.4 working copy.

## Preserve

- The project switcher and search live in the workspace header.
- Keep the six existing work areas. Group them by user intent without adding
  first-level destinations.
- Start the overview with actual project purpose, boundaries, core knowledge,
  and work that needs attention.
- Let people read Features through business intent, rules, cases, and design.
  Use the three business tabs where they fit the knowledge type.
- Prefer condition tables and readable text over automatic diagrams.
- Hide internal UUIDs and slugs from primary user-facing labels. Keep exact IDs
  available only where operators need technical traceability.
- Keep a lightweight project assistant and feedback entry in the current context.

## Do not infer

The prototypes are design evidence, not product behavior. Local storage, demo
roles, simulated approvals, and mock delivery records must not become production
facts. T1.0 defines real permissions, persisted state, approval, publication,
Agent, test, and deployment behavior.

## Provenance

`checkpoint-v9.3-1207759.tar.gz` and `working-v9.4.tar.gz` remain preserved. The
V9.3 review at `../baselines/T1.0/05_原始基线/V9.3原评审报告.md` records why the
reading and task semantics were changed. V9.4 is excluded as a design authority
by the current product owner instruction.
