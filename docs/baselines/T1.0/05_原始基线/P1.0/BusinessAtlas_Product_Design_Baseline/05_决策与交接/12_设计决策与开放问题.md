## 4. 给负责人的推荐审阅事项（少而重要）

1. 产品核心是否准确：轻入口、重治理、业务语义及真实开发知识资产；若正确，采用 P-01~12 作为产品原则。
2. 三 Tab 与按需扩展是否能作为默认功能表达；真实案例阅读结果是评审依据，不需亲自确认每个底层字段。
3. 知识审批是否按授权人/风险聚合、批准与发布分开、候选和观察不得冒充规范；是否接受推荐的业务/技术边界。
4. 原型不画图已明确；建议把正式产品图形专项需求改为可选未来评估，保存流程/状态的语义及历史，不把绘图当正式交付门槛。此项需你明确正式范围。
5. 采用真实 CPQ 与真实 Self Project 验证；未提供真实规则时保持未知，不把演练当实际知识。具体事实后续由 BA 和资料提供者处理。

其他设计选择如无实质冲突，推荐按本稿采用；变更时记录 ID、变更前后、理由、受影响文档/要求、批准主体及生效版本。不要让下一 Agent 再逐项询问已明确的方向。
