# Business Atlas｜产品研究与设计基线 P1.0（待审）

**编制日期：2026-11-19 · 性质：产品定义与语义治理设计候选稿 · 适用对象：产品负责人、BA、架构与技术设计 Leader、开发/验证 Agent。**

这不是 V9.5 原型，也不是生产实现。它是从用户提出的产品意图出发、结合 V1.0–V1.2 已有交付和 V9.3 发现的问题，对业务知识如何组织、定义、审核、使用、变更和呈现所做的完整产品层设计。此处版本 P1.0 独立于工程版本 V1.2，避免混淆。

## 先审什么

Business Atlas 是面向软件项目的共同认知与持续知识治理平台。它将项目中的领域语言、需求、业务规则、行为、实现、约束及证据组织为可持续演进的知识资产。AI 与平台负责复杂的调查、解构、组合、传播、校验和版本维护；人主要阅读、评审、确认和验收有意义的业务与工程成果。

**关键取舍：底层重，入口轻；事实一套，表达多样；开发与知识共同演进。** 不是一个由几十种对象页面组成的百科，不是工作流图软件，不是独立编程 Agent 调度器。优先证明读者能理解真实业务判断、Agent 能用已确认的知识工作、变更后不会破坏其他业务规则。

## 权威/状态说明

- **U（用户明确意图）**：直接来自用户讨论；如文字优先、不要堆叠字段和绘图、完整交付、关键业务决策由人审核、知识伴随开发演进。本稿记录该意图；不冒充逐条正式签署。
- **R（设计建议）**：本次独立提出的候选设计，供评审。普通设计选择已给出推荐，不把所有选项推回用户。
- **O（观察/历史输入）**：历史文件、源码观察或用户报告；不能自动升格为规范。
- **X（未知/待验证）**：需要真实项目资料、业务确认或产品试点验证。
- **示例**：黄金案例中 `EX-` 对象是虚构的可重复演练，而不是公司 CPQ 的实际批准规则。真实 CPQ 的完整源码、业务字段、审批意见未提供，本稿不会编造实际规则与完成率。

解释设计意图时以用户明确表达的方向为依据；执行项目工作时以经正式批准且适用的知识为约束。当前任何历史候选稿均不能视为实际签署。新用户意见与已批准规范冲突时，要形成明确变更决策，不能按“最新话语优先”直接覆盖。工程 V1.2 继续作为工程合同参考，产品设计差异按第13份文件登记；未批准的替代建议不能静默覆盖已有契约。

## 交付边界

本包仅含 Markdown、CSV 与校验清单，无生产代码、无新增原型、无自动化测试工程。它覆盖产品定义与逻辑合同，给出完整的目标产品范围、场景和可验收要求；真实 API、数据库结构、部署及生产安全实现继续由正式开发阶段负责。当前未连接 CPQ 仓库、真实 Agent 或用户系统，因此影响召回率、认知效率、实际审批流程适配均待实证。全部设计可按本稿直接进入评审，无需重读此前几十轮对话。
