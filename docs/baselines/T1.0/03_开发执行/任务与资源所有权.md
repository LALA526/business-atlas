## 执行与依赖

- `task-dag.json` 为任务合同，包含预计路径、依赖、具体实现、测试ID、关联需求与知识输出。`requirements-trace.csv` 保留116项历史+38项P1要求及原验收原文；映射是计划，不是实际证明。工程负责人在实际创建Azure Boards时用稳定T-ID作外部键，不按标题匹配。
- 任务 T01 是合同/范围Owner，T03 是migration唯一Owner；各业务Agent提交schema变更请求，不并行修改共享迁移。T31与T39按依赖共同由ReleaseOwner合并唯一pipeline，业务CI插件在独立路径；所有新共享接口先由Owner冻结精确schema和版本，消费者以生成client实现。
- Azure Boards下 Epic=完整产品，Feature=模块/能力，User Story=上述Task（小队可拆子任务），均链接 PD/BA/ENG。开发任务Coordinator使用CAS/租约/资源锁和Git PR事实，不以聊天记录为状态机。每任务使用 `task/Txx` 计划分支；在实际机器配置 worktree root（Windows默认 D:\Multica\runs，Mac使用专用数据目录；缺目录由协调器按实际环境建立）。
- 工程编排与Atlas产品的外部Agent服务是两套职责：前者用现有 Azure/Git/CI/持久账本；后者为最终产品知识与任务协作接口。无需先另造通用多Agent平台。可沿用V1.2 SQLite参考账本，增补PD识别/新版DAG adapter；状态以实际Azure和PR核对。
- Reviewer独立于实施者，安全/领域Owner独立批准需权限的内容。失败保存原因、实际产物和checkpoint；重试前检查lease/fence、base/contract digest及关联B；并行PR改变共享合同则冻结受影响任务并重新生成上下文。未受影响任务继续。
- QA将逐条历史测试ID与AT-P01..14及AT-Txx映射到真实自动化用例/人工脚本，并附实现hash、实际结果和环境。不以测试数量衡量质量。最终G7要求逐条回填，不可用宽泛工作包名称代替证明。

## 接口唯一实施责任与首个PR知识门禁

`operation-ownership.csv` 列出114个operationId的一对一实现责任Task。`task-dag.json.operationIds` 指任务需要阅读/使用的合同范围，并非授予其重复实现权；对每个API只允许对应责任Task创建/修改handler，消费方通过合同、Port与生成客户端调用，需修改时先向Owner发起合同变更。模块Owner和Migration Owner共同控制共享文件。

T02的启动工作中即建立Git知识候选账本、PR校验和合并Manifest初版，首个启动PR保存真实候选及合并证据；不等待T31后端支持。T31接续已运行的协议，补真实后端摄入、对账及历史回放；T38真实Self Project使用已有账本并审核发布。若平台CI尚未配置，保留真实本地Git候选/commit并明确CI未启用，不冒充合并流水线完成。
