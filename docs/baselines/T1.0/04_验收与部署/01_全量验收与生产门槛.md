## 1. 完整不变量回归

| INV | 独立验证设计 |
|---|---|
| 01 项目隔离 | 两项目同名概念和实体ID，列表/直接ID/成员/写入/导出均隔离 |
| 02 稳定身份 | rename、同包导入、字段映射重命名，引用不重建；同外部ID异hash冲突 |
| 03 不可变历史 | B1成员/修订/属性/hash在B2/回退B3后保持；旧schema按当时语义读取 |
| 04 草稿隔离 | 正式首页/目录/检索/助手/导出/Task不得出现draft，草稿明确授权 |
| 05 原子事务 | 注入每步异常、断电、重复/并发，DB无半基线、半导入、假audit |
| 06 端到端权限 | 直接HTTP、DOM、MCP/来源、历史/导出、缓存/引用侧信道负例 |
| 07 适用性四态 | known applicable / not applicable / unknown / conflict按生产、测试、缺值、相反事实验证 |
| 08 事实不等于批准 | 观察、推断、候选均不能自动批准规范；相反观察可共存 |
| 09 Flow保真 | 七阶段/十二节点/十四边、两ruleRefs与guard、异常和回流保留；真实阅读文字非虚构排序 |
| 10 表达无事实副作用 | 改Tab、折叠、焦点、显示方式/外部图引用，不改变批准hash；原布局专测据Owner范围裁定改为文字语义测试 |
| 11 来源定位 | commit/blob/locator和source revision精确，漂移后需复核；撤权后不泄露 |
| 12 契约重授权 | 管理员生成合同不使Reader/Agent提升权限，policy变化与历史/导出正确 |
| 13 治理快照分离 | Task、Issue、评论、反馈与审批变更不直接改旧知识 |
| 14 不确定透明 | 缺必要规则/条件/证据/权限，读/评估/任务明确未知，不能伪造完成 |

## 4. 生产测试要求（建议目标，尚未实测）

- 基础：Domain单元（条件/语义/状态机、CAS决策）；真实PG Integration（迁移、FK、RLS、封闭、事务、并发、import）；Contract（OpenAPI有效性、生成client、Schema正反、MCP input/output、事件兼容）；Security（JWT audience/CSRF、路径穿越、跨项目、隐私、模型注入、存储/导出）；Browser E2E（实服务、非fixture），GoldenSemantic独立业务参考。全部关键负例必须保留。不要为每个UI徽章设自动断言。CI PR跑受影响任务+核心安全；merge跑集成；release跑全量和人工关键旅程；测试失败附真实日志。
- 容量初始目标：1万知识单元/10万关系、100个基线（真实混合样本，报告总磁盘和单次发布新增量）；5并发人+2外部Agent，无越权，无半写，普通知识查询p95≤700ms、复杂有界阅读p95≤1.5s，搜索p95≤1s（不含模型和网络，记录查询规模及冷/热缓存）；长任务异步，提交≤2s。模型单独统计首字节、总延迟、429、token和成本，不承诺模型固定延迟。不能为达标关闭安全或省略语义。至少10k样本验证全量基线合理，必要时记录ADR切增量实现。
- 8GB Mac实测目标：系统保留≥1.5GB可用余量，无持续swap压力、OOM或服务重启；真正运行全部必需组件。若不满足，先降不必要并发、IdP迁外，不删产品功能；仍不满足走明确资源变更。测量工具/环境、镜像/commit、数据集、时间以及峰值一并交付。
- 安全：无未处置高危/严重依赖漏洞、secret扫描通过；有风险例外必须审批、有期限，不能豁免数据/权限阻断。真实备份与恢复验证不可用“命令应该能跑”代替。
