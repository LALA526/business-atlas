# 安装、发布、运行和恢复实施手册

本文件规定ReleaseOwner必须实现的部署流程。默认 Windows开发、Mac mini M1 8GB Linux ARM64容器运行；账号、域名、实际机型/系统和存储需实际验证。不把开发机或未启动的Compose声明为已部署。

## 1. 环境初始化与工程脚本

Windows/CI安装git、.NET10 SDK（固定global.json补丁）、Node24 LTS（package lock）、Docker或等价容器环境；从清洁repo checkout运行 `dotnet restore --locked-mode; dotnet build -c Release --no-restore; dotnet test -c Release`、Web `npm ci; npm run typecheck; npm run build; npm run test`；实际命令需写入根build/check脚本并用CI验证。`contracts`检查、OpenAPI生成client、PG实迁移、真实E2E独立配置；Windows与Linux路径大小写兼容。开发可 `docker compose --profile dev up -d db idp`，prod严禁dev默认密码与OIDC insecure模式。Arm host采用受控Colima或现有Docker Desktop，先检查arm64、容器架构和可用盘、备份目录、vm memory/cpu。构建在CI完成，主机只pull与运行。

## 2. 最终部署文件要实际存在

| 路径 | 真功能 |
|---|---|
| `deploy/compose/compose.yaml` | db、api、worker、proxy、可选idp；无公开DB/worker端口；各服务healthcheck、restart、limits和持久volumes；one-shot migrate以专用role运行；migration成功才启动新版本 |
| `deploy/proxy/Caddyfile` | 唯一外部HTTPS入口，TLS、同源、web静态、API/MCP/SSE/SignalR正确转发，上传大小及超时、禁止敏感日志 |
| `deploy/identity/` | OIDC应用/client/audience/provider配置说明，回调URL、Token密钥轮换、与角色映射；现有IdP优先，Keycloak可另机 |
| `deploy/backup/` | 备份、校验、恢复、保留和WAL归档脚本，定时任务与告警 |
| `deploy/ops/` | health/metrics、日志rotate、告警规则、容量和故障runbook |
| `scripts/deploy`、`scripts/rollback` | release digest参数、锁、预检、备份、迁移、健康验证、失败停止与回滚；真实结果上传CI |
| `.env.example` | 仅非敏感端口/路径/示例地址与secret文件路径，不包含真实token |

建议小型初始分配（须实测）：db shared_buffers 256MiB、连接池总<=40，DB容器1.5GB，API 1GB，Worker 1GB低并发（2外部工作请求），Caddy 128MB；主机冗余和VM开销实测。IdP另机优先（Keycloak生产约2GB建议）；同机需重新测量。不在Mac本地启动模型或全量构建。开发默认用真实外部模型开放API（需用户授权、配置endpoint/模型/密钥及预算）；无账号则标明未接入，不能上线宣称Agent可用。

## 3. 配置和权限

固定 `ATLAS_PUBLIC_URL`, DB host/name、runtime/worker与独立migration/backup身份、OIDC issuer/client id/audience/callback、MCP resource metadata、`BLOB_ROOT`, `BACKUP_ROOT`, upload limits、provider endpoint/model/secretRef、默认预算/worker并发、log retention/configDigest。生产密钥以owner仅可读文件或受管secret注入，不进入git、镜像、浏览器、prompt、日志、CI输出。密钥轮换可撤销，API/worker/CI用独立主体最小权限。数据库 runtime `NOSUPERUSER NOBYPASSRLS`、非owner、不具有可切换DDL role权限；设project scope仅在已授权应用事务中，连接池清理，RLS与服务层共同约束。迁移role隔离，备份role只用于批准备份/恢复。库/附件不直接暴露；TLS证书由用户控制或公司CA。内网/Tailscale部署亦启用认证、审计和TLS。模型外发资料遵循项目权限与数据治理，不自动发送密钥或整个repo。

## 4. 发布顺序（自动化必须包含）

1. Azure pipeline checkout绑定commit，恢复锁定依赖、构建/测试、扫描漏洞、SBOM及许可证、容器multiarch构建并固定digest。生成真实知识Manifest（独立于commit），校验候选、源blob、CI身份、artifact。
2. release owner确认目标、批准范围、上版镜像与迁移版本、磁盘/secret/IdP/DB可用、是否需要维护停写。取部署锁，建立部署前DB+blob一致备份并校验。不可逆迁移必须提前审批；优先expand/backfill/contract，旧版本兼容期内保留字段。
3. `docker compose config`验证，不打印秘密；pull已固定digest；先运行one-shot migration，不多实例争抢。失败保留日志、停止发布并按备份策略恢复。启动新版API/worker/proxy，依赖ready检查，不将/health/live等同可用。
4. 真实smoke：登录、项目及权限、打开规则、历史、创建候选审批，MCP OAuth与受控工具、模型读/引用、后台Job恢复、附件授权、真实部署对账。附上实际版本、时间、host、环境、commit/migration/config digest、停止/成功结果。
5. 通过才记录部署成功及reconciliation；失败标failed、保有上个部署证据。若DB/schema兼容，回到上个镜像digest；若不兼容，停止写入并隔离恢复一致备份，确认恢复点及数据损失影响后切换。知识回滚是新批准基线，不同于DB灾难恢复。

## 5. 备份与一致性恢复

试运行最低RPO 24h/RTO 2h（目标，实测确认）；关键生产采用Postgres base backup+连续WAL归档以支持PITR，RPO目标15min，按实际环境与批准的风险设定。每日DB逻辑备份+不可变blob快照用于交接/小规模恢复。备份时置维护门或一致事件边界，停止新写/GC，确保所有DB引用blob已经落盘；记录snapshot/LSN、DB和blob清单/hash、schema/migration、应用镜像和配置版本；保留在另一物理故障域加密。初始建议7日每日、4周每周、3月每月，按数据治理调整。仅本机另一目录不算灾难备份。备份失败、过期、WAL归档落后、磁盘不足立刻告警。

恢复演练：隔离临时环境→验证密钥和hash→恢复DB到选定点→恢复全部引用blob并验证完整性→运行对应应用版本及真实migration一致性→验证baseline hash/权限/历史/来源/任务/部署记录→再经过授权切换目标，记录恢复前后差异、耗时、数据丢失窗口、审批、处置。保留业务知识的历史基线而不是直接改指针。至少一次实际空机恢复与一次PITR，不以脚本存在代替演练。

## 6. 可观测与运维

结构化日志含requestId、project匿名标识、actor授权标识、job/task/run/commit、duration和错误类别；不写业务敏感正文/token/模型密钥；按权限查询。OpenTelemetry trace/metrics，初始可用本地日志/metrics+既有监控，不强制重量级集群。关注p95请求、DB锁/连接池/存储、outbox积压、job超期/fence/失败、provider延迟/429/token成本、审批/知识债、manifest和部署分歧、备份时效、容器重启及内存。设置告警可被人收到、故障分级、可复现runbook；测试告警路径。针对Mac断电/睡眠/虚拟机重启，配置实际自启动，并验证Worker恢复、未完成事务和DB完整性。定期补丁、密钥轮换、清理过期未引用blob，禁止GC破坏任何历史或备份。生产发布不允许无审计的手工热修。
