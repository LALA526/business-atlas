# 01 技术目标架构、范围和选型决定

关联：P1.0 01–03、07、08、11–14；V1.2 M01–M12、INV-01..14、G0–G7。所有具体选型是 T1.0 实施决定候选，除范围、真实业务、权限/费用等须人确定事项外，Leader 直接按默认实现，失败用实测证据变更 ADR，不能让每个开发 Agent 重选技术栈。

## A. 正式产品必须完成的能力

- 项目空间：空项目创建、成员、角色、范围、背景、标准五维知识目录、可扩展类型与谓词、术语/别名/语境/属性、知识搜索和定位。管理的是任意目标项目，不是只管理 Business Atlas。
- 语义核心：稳定身份、版本化实体/断言/关系/Flow/状态/源码来源，规范与实际观察分离、内容契约、可判定业务规则、关联需求/行为/实现/案例、文本组合视图及受控导出。业务需求/规则/业务设计默认三个 Tab；按需内容，不新造页面。
- 治理：Draft、ChangeSet、人类审批、驳回/重新提交、版本比较与原子发布、历史读取、适用性、证据和冲突；来源/字段级权限独立，两端点校验、审批可读性、撤权后的重新授权。
- 开发协作：Task/Issue/反馈/评论和真实协作，轻量需求入口，AI 识别目标/保持/未知，候选影响、实际调查、方案比较、传播、验收与回写，决策授权、上下文失效；对空泛需求不制造合同，不能把十五类影响表交还给人。
- AI：真实检索/生成/引文检查、外部 Agent MCP/REST、持久运行记录、真实证据分类、取消/预算/故障恢复；15项CS逻辑服务，同一应用层授权；Skill用于调用顺序，不是内建编程 Agent。真实开发工具可在授权的执行端调用仓库，不把shell直接暴露给模型。
- 工程交付：Git PR 候选知识、合并后Manifest、CI证据、知识治理和部署对账、真实 Self Project、错误模式记录；正式安装、备份恢复、审计、并发、安全、性能、供应链与维护。完整产品在同一目标范围交付。

**范围裁定建议：** BA-VIS-001/004/007/008 暂不实现专用绘图、画布布局、热点编辑、图形导出；BA-VIS-002/003/006 改为文本守恒、关系语义和焦点返回；005保留多种表达。保留外部图附件与描述/引用、Flow/State语义及历史导入，禁止引入布局引擎。此决定对应 DEC-07/Q-03，G0需Owner确认正式替代；目前建议按最新“文字优先、原型不要图”做减法。若不同意，先审范围更改，不默默重启图形工程。INV-10 扩展为任何呈现、折叠、焦点等操作不能变更知识事实。V1.2 原流程/权限/草稿/符合性缺陷均未减免。

## B. 选型与部署拓扑

| 层 | 默认决定 | 取舍/验证 |
|---|---|---|
| Runtime | .NET SDK/runtime 10 LTS + ASP.NET Core 10 + EF Core 10 + Npgsql 10；锁定补丁 | 官方支持期到2028-11-14；采用成熟性及维护目标，非声称比 .NET 11 支持更久；版本锁、依赖许可证与CVEs在G0/G1核验 |
| Web | React 19、TypeScript strict、Vite、React Router、TanStack Query、普通 CSS design tokens；Markdown+受限结构化 blocks | UI不直读库；无需Next SSR、图形引擎或复杂富文本协作. 使用已维护的Markdown解析/净化库，默认禁止raw HTML. Node 24 LTS补丁锁与peer兼容实测 |
| Database | PostgreSQL 17最新安全补丁；一个 DB，按模块 schema；EF migrations、参数化SQL、必要递归CTE+GIN/pg_trgm | 成熟稳定，Npgsql支持，ARM64镜像及extension在CI验证；以17为基线而非追求18新特性. 不采用图DB/ES作第一权威事实源 |
| Auth | OIDC授权服务器（默认可用现有OIDC；无则Keycloak稳定版生产配置，优先部署其他机器，试点可同机） | 浏览器Authorization Code+PKCE与BFF安全cookie；API/MCP独立audience token，内部人员角色在Atlas DB. Keycloak官方小型生产建议2GB，必须实测8GB；不能因资源不足关闭认证 |
| Storage | IBlobStore：本地私有挂载目录的不可变hash对象；企业可替换S3 adapter | 临时上传→扫描/hash→原子rename→DB提交引用；无公开目录；备份DB及blob一致. 首版默认不部署MinIO |
| Jobs | PostgreSQL outbox、job、inbox tables + .NET Worker | `FOR UPDATE SKIP LOCKED`/lease/fence、幂等、恢复；无需Temporal/Redis/RabbitMQ。实际高负载证据才支持替换 |
| Search | PostgreSQL exact alias + trigram + FTS(simple)（中文验收加Unicode子串/二元词法候选），ACL前后重验 | 查询词用于知识检索，不等于CPQ业务搜索规则。默认不依赖embedding；大规模再以真实检索质量POC决定 |
| Realtime | SignalR / 同源Hub，通知仅 opaque event + 当前授权重新查询 | CAS是事实写入约束；不把CRDT用于批准语义。多人评论、审核变更通知及冲突提示需真实实现 |
| AI/MCP | 真实 provider adapter（首个支持OpenAI兼容HTTP API，配置endpoint/key/model），官方受支持MCP SDK的Streamable HTTP + OAuth资源服务器 | SDK与可用客户端握手/权限需实测，凭据不进入前端。集成模型不能直接发SQL或批准。外部agent本地调查真实repo，平台有持久请求/事件/证据 |
| Ops | Docker Compose Linux ARM64 on Mac（Colima或现有受控Docker Desktop），反向代理 TLS，CI构建multiarch制品 | Windows开发；CI备份/健康/迁移/回滚；不在8GB host本地跑大模型或编译全仓库。Ubuntu/Linux部署同配置 |

**不是多套架构方案让用户选：** 默认组合为 API(BFF + MCP adapter + static Web)、Worker、DB、IdP(尽量复用/另机)、反向代理、私有volume。Web静态构建随API镜像发布；Worker和API可以同一 .NET solution，不需要每模块进程。外部 Agent 通过 API/MCP 和受控本地执行器访问项目资料，上传证据，不能直接访问平台数据库。运维与资源阈值详见部署文档。内部模型调用与工具任务不可无限等待；队列、过期、取消、持久checkpoint由M12提供。

## C. 模块所有权与依赖

保留 V1.1/V1.2 模块 ID，明确 P1.0 新需求，不新造平行领域。每个模块 Domain/Application/Infrastructure/Contracts 由唯一Owner负责；接口通过应用层，跨模块事务由单一Orchestrator/UoW协调，模块仅写自己schema，通过端口查询其它领域。

| ID / 代码目录 | 数据所有权 | 公共端口/职责 | 禁止 |
|---|---|---|---|
| M01 ProjectIdentity | project, principal, membership, project profile pointer | IProjectDirectory, IMembership, ISubjectResolver；新建与隔离，身份外部sub映射 | 由客户端role决定权限 |
| M02 SchemaCatalog | registry metadata；type/predicate/profile知識定义由M03存储，M02校验 | ITypeRegistry, IPredicateRegistry, IContentProfile；五维、扩展、型版本 | 同义谓词重复、用技术schema覆盖业务定义 |
| M03 KnowledgeCore | unit, revision, revision_ref, relation_index, external_identity, evidence_link | IKnowledgeStore, IRuleEvaluator, IFlowSemantics, IRevisionFactory | 可变批准修订、把布局作为事实 |
| M04 AccessApplicability | policy/field labels, resource grant, policy epoch | IAccessPolicy, IReadContextFactory, IApplicabilityResolver | UI/filter绕过、关系/来源泄露 |
| M05 Governance | change_set/item, review, baseline/entries, publish | IChangeSet, IApprovalPolicy, IBaselinePublisher/Resolver | 审批和发布混同、未批自动改facts |
| M06 ImportEvidence | blob, upload, import_batch/entry/decision, external evidence intake | IBlobStore, IPackageImport, ISourceIntake | 部分导入成正式、相同外部ID静默覆盖 |
| M07 ReadSearchExplain | search cache/index、reading projection (派生) | ISearch, IReadingPlan, IVocabularyRead, IContentCheck, IConformanceRead | 独立可写事实、过期标签为真相、unlimited投影 |
| M08 TaskCollab | task, issue, comment, feedback, activity, impact记录/调查 | ITask, IImpactInvestigation, IChangePlanner, ICollaboration | 用户原话即完整任务；任务done直接改规范 |
| M09 ContractDelivery | task_context, context_dependency, conformance check, acceptance, delivery/deployment/knowledge debt | ITaskContext, IClosure, IDeliveryReconciler | 读旧契约绕权、commit=审批 |
| M10 Assistant | conversation/message/citation, provider config(仅secret ref) | IConversation, IProvider, IReasoningRun | 把LLM输出当已验证事实/无限工具 |
| M11 AgentMcp | agent_run/event, agent work request & evidence proposal refs | IAgentRun, IInvestigationRequest, IMcpDispatch, IProposalIntake | raw db/提升权限/自动审批 |
| M12 PlatformOps | jobs, idempotency, audit, outbox/inbox, alerts, error patterns | IJobQueue, IAudit, IOutbox, IUnitOfWork, IEventBus | 异步代替原子发布、依赖全历史prompt |

依赖顺序：BuildingBlocks不依赖任何业务模块；M01/04提供主体、权限及上下文；M02/M03持有类型语义与修订；M05协调M03/M04发布；M06经M03/M05进候选；M07通过M04/M05/M03读取；M08通过M07与M05调查和提案；M09通过M08及治理/证据对账；M10/M11只调用已定义应用服务；M12基础能力被注入，不反向引用领域实现。跨模块公开 Contracts 项目可互引其 DTO，运行循环由 composition root/ports 解决，不允许 Domain 引用另模块 Infrastructure。DB FK 是数据完整性约束不是越权读取许可。EF迁移集中生成/应用，SchemaOwner审批每个模块DDL，跨模块共享迁移串行。

## D. 代码结构（创建目标，而非声称存在）

```text
business-atlas/
  BusinessAtlas.slnx   global.json   Directory.Build.props   Directory.Packages.props
  apps/Atlas.Api/       # Composition, BFF, REST, MCP, Hub, serve wwwroot
  apps/Atlas.Worker/    # jobs/outbox, import, async AI, index, reconcile
  apps/web/             # src/routes + features/{project,knowledge,review,task,delivery,assistant}
  src/BuildingBlocks/   # Result, ID, clocks, version/hash, command pipeline, transaction
  src/Modules/{ProjectIdentity,SchemaCatalog,KnowledgeCore,AccessApplicability,
    Governance,ImportEvidence,ReadSearchExplain,TaskCollab,ContractDelivery,Assistant,AgentMcp,PlatformOps}/
     Domain/ Application/ Infrastructure/ Contracts/  # 小模块可合并目录，但所有权不变
  contracts/{openapi,schemas,registry,akp,mcp,knowledge-delivery}/
  db/migrations/       # 唯一 owner，EF生成并评审，不运行两套DDL迁移
  tests/{Domain,Integration,Contract,Security,EndToEnd,GoldenSemantic}/
  knowledge/{baseline,proposals,decisions,error-patterns}/
  deploy/{compose,proxy,identity,backup,ops}/   scripts/  docs/
  azure-pipelines.yml  AGENTS.md
```

共享 contracts/OpenAPI 由 T01合同 Owner 接管。根据本包实际文件名复制为仓库技术约定路径，机器规范版本及hash固定。各模块不得在 UI 手写另一套未登记 DTO；使用OpenAPI生成 TS client，业务视图组件只消费其 DTO。所有运行时依赖版本经lockfile管理；构建/测试/部署脚本必须在干净环境运行，不依赖IDE本地隐藏状态。

## E. 必须验证的架构决定（可并行，不作为独立完成阶段）

| ADR | 首选默认 | 必须提供验证/触发改选条件 |
|---|---|---|
| ADR-T01 | 模块化单体+单PG+worker | 用架构测试验证禁止跨Infra引用；真实跨模块publish单事务；无需微服务避免分布式一致性 |
| ADR-T02 | 全量不可变baseline membership | 1万/10万单元、关系与100次基线样本，历史页/diff/publish/磁盘，达不到目标才切增量checkpoint，外部语义不变 |
| ADR-T03 | OIDC+应用授权+pg schema/RLS项目隔离 | 双项目、字段/source、历史/cache/MCP、撤权、token audience负例；未通过生产拒收，不为速度移除 |
| ADR-T04 | 候选影响有语义、实际调查由外部Agent提供 | 在已知隐藏调用、动态配置、字段语义反例的真实Repo验证，不宣传完全召回；外部证据受权核验 |
| ADR-T05 | PG搜索、无图/向量服务 | 多语言词汇/同义词/中文业务/ACL召回、性能测试；只在真实质量不足且收益可证时加入新索引 |
| ADR-T06 | PG持久Job/Outbox | 中途kill worker、租约争夺、重复提交、取消、网络超时、恢复；达不到SLO才考虑新调度Adapter |
| ADR-T07 | 文件存储本地+一致快照备份 | 私有访问、hash、故障/恢复、容量测试；多实例并发部署时S3 adapter有必要再切换 |
| ADR-T08 | Mac ARM64 小型环境 | 资源/完整运行/ARM64 SDK与镜像、备份/恢复；IdP优先另机，若仍超资源由实测提出部署资源变更 |
| ADR-T09 | 实际模型/工具合同 | OIDC/MCP真实auth、引用、外部Agent证据、成本/取消、防注入；协议能力不足禁止mock充数 |

## F. 参考核对（2026-11-19）

- .NET支持政策：https://dotnet.microsoft.com/en-us/platform/support/policy （10 LTS，最新安全补丁以实际安装时为准）。
- Npgsql EF Core 10 release notes：https://www.npgsql.org/efcore/release-notes/10.0.html 。
- PostgreSQL 17 RLS：https://www.postgresql.org/docs/17/ddl-rowsecurity.html （表owner/约束与侧信道，不能只用 RLS 假定端到端安全）。
- Keycloak容器官方说明：https://www.keycloak.org/server/containers （生产配置与内存限制）。
- MCP官方规范发布：https://blog.modelcontextprotocol.io/posts/2026-07-28/ ，https://modelcontextprotocol.io/ （按SDK实际支持与客户端协商版本；HTTP transport/OAuth资源服务器、工具权限，不能硬编码假定旧协议永远最新）。

上述为选型依据核对，不是依赖漏洞、实际ARM64运行、性能或生产部署测试。锁定工具包、SDK、镜像digest和许可证清单必须由Leader在实际仓库产生。沿用P1.0概念来源与原V1.2工程依据，避免照搬大型开源平台全部基础设施。
