# 09 统一安全、审计、后台作业和并发恢复

## 1. 威胁模型与授权矩阵

攻击面：项目越权/ID枚举、角色自报、字段/来源/历史泄漏、共享缓存/搜索/导出/助手旁路、CSRF/XSS、恶意导入/路径、模型prompt injection/SSRF/日志泄漏、Agent冒充审批/CI、重复消息/竞态/租约失效、数据丢失、真实部署秘密暴露。默认deny，最小权限与服务分权。

| 角色（可组合） | 默认权限 | 禁止 |
|---|---|---|
| ProjectReader | project scope内已发布授权知识、source授权的摘要、查看历史需read_history；按配置提问/反馈 | 创建/更改Task、候选、审批或发布 |
| Contributor / AgentProposer | 读自己有权版本，创建Task/Issue/评论、草稿、调查和proposal、提交审核 | 删除历史、授予权限、自己批准业务规范 |
| BusinessOwner | 审批业务需求/规则/领域语义/业务验收 | 代替QA证明实际测试、绕过Security approval |
| TechOwner | 技术合同/职责/设计审批，授权内技术决定 | 随意改变业务行为或权限 |
| Verifier/QA | 核验证据、记录实际测试、acceptance、revalidate | 修改目标规范方便通过 |
| KnowledgePublisher | 在全部必要有效批准后发布基线、治理身份 | 未批准/冲突/不可读关键证据时publish |
| SecurityOwner/DataOwner | 敏感资料/授权/不可逆变更批准、审计视图 | 业务审批自动继承、直接绕过不可变性 |
| ProjectAdmin | 项目成员和role/政策维护、配置（关键授权需要Security/owner政策） | 从管理员身份自动获得业务审批或能读所有受限source |
| CIService | 指定repo/project的manifest/actual test/deployment ingestion | 生成未经授权的业务规则、读取整个资料库 |
| WorkerService | 用有效job scope执行允许的应用Port，独立调度claim最小role | 常驻全库原始读取、提高代办者权限 |

Principal由OIDC issuer+sub严格绑定，人的browser以BFF会话cookie+CSRF、Origin；OAuth client credentials适用独立服务，权限绑定scope和project，不信`roles` claim直接当业务批准者。MCP独立audience，token不得转发给其他服务。人类审批必须human principal + role + 当前授权且风险审批区分；普通Agent不成为human。最小scopes采用 `atlas.read, atlas.propose, atlas.task, atlas.review, atlas.publish, atlas.admin, atlas.evidence, atlas.ci, atlas.agent`；scope只是上限，后端membership/owner/资源ACL仍判断。未登录401，已知有权对象动作不足403，对不应知道存在的对象统一404。安全日志记录actor/request/operation/deny category，不泄露敏感内容。

## 2. 统一Read/Write boundary

`AuthorizedReadContext`只能通过`IReadContextFactory`生成，不接受client role/clearance/权限结论；包含project、subject、policyEpoch、baseline、mode、applicability/asOf、purpose、allowed field mask及source policy。查询根、所有引用及关系两端逐个授权，业务术语/观察/证据与摘要各有visibility；受限字段不能在投影、序列化、标题、计数、rank、搜索/AI答案、图（已移除）、历史、合同/导出中侧信道泄露。权限授予独立于approved，当前撤权覆盖历史。`AuthorizeCommand`检查action、主体kind、aggregate/project、目标/来源/required_refs、状态/风险/审批，不能仅通过能读实体就createTask。读取/引用无法授权关键信息则`CONTEXT_INSUFFICIENT`或隐藏的403/404，不自动跳过后给出“全部完成”。源下载通过短期一次性或受控stream，不公开文件系统路径；签名URL若不能立即撤销默认server streaming，打开/续传重新授权；已经合法下载到用户设备的旧副本无法技术撤回，须有企业留存策略。

DB使用project RLS强制隔离及FK，app角色非owner/无BYPASSRLS；应用授权更细（对象/字段）。当前policyEpoch增量与membership/grant写在同一事务；所有查询、授权cache、合同、job result、SSE/SignalR、搜索和导出在发出敏感数据前检查epoch，若长流中变化停止并清理。使用角色授权测试覆盖10+入口；管理员生成的合同普通Reader不能重放。拒绝将可猜资源ID、受限relation count、FK错误细节回给无权者。后端从server获取授权模型，浏览器按钮不是安全防线。

## 3. 输入与AI工具边界

SQL只参数化，EF及必要原生SQL都不拼输入为语句；限制分页、AST大小/深度、导入解压、上传content、Markdown净化、URL允许scheme、CSRF/CORS、TLS。静态文件和source私有目录隔离；防路径穿越/符号链接/私有网络SSRF，外部URL默认不fetch。Provider endpoint由服务器admin allowlist，不能由用户消息控制；外部模型出站数据需明确项目policy和授权，敏感来源不自动送模型。AI提示/文档/工具返回作为不可信资料，模型不能提升role、触发server shell、打开任意文件或网络。工具schema与server allowlist+action policy+budget一致。不在普通日志、错误响应、model prompt/trace输出secret，source片段只在有权结果中显示。真实代码/测试/CI evidence需身份验证+hash/locator，普通Agent自写摘要标reconstructed；用户反馈并非授权掉其它规则。

## 4. Job、Outbox、事件、恢复（不另造分布式系统）

Job state：queued→running→succeeded/failed/canceled；running→waiting_external/queued（可恢复）；cancel_requested由worker检查lease，停止提交业务副作用；lease_expires/attempt/fencing_token单调。`claim`使用独立调度Port在短事务 `SELECT ... FOR UPDATE SKIP LOCKED`挑`available_at<=now`且状态queued/expired running，设置worker/leaseUntil/fence+1/attempt；提交后执行外部调用，不在持锁时等模型。每30s heartbeat（lease 120s默认），结果commit时按jobId+fence+state CAS；旧worker不能写当前业务结果或推进完成。必要时结果仅归档为stale证据。`waiting_external`不占运行lease；外部work request有独立claim/fence；restart可从durable checkpoint续跑。对同job同一领域副作用用稳定 idempotencyKey=jobId:step:inputDigest，不能靠重试产生重复发布/候选。非幂等外部操作先检查实际状态/外部correlation，失败不自动重复不可逆命令。

Outbox append与领域事务同commit；M12 poller短claim/lease，consumer根据eventId+consumerKey唯一Inbox去重；处理成功同事务记录Inbox和业务副作用（外部副作用使用幂等协议），至少一次，不承诺exactly-once网络。事件`BaselinePublished.v1`,`AccessPolicyChanged.v1`,`KnowledgeCommandApplied.v1`,`ChangeSetReviewed.v1`,`TaskStateChanged.v1`,`ImportStaged.v1`,`AgentRunEventAdded.v1`,`KnowledgeDeliveryRecorded.v1`,`DeploymentRecorded.v1`,`ContextInvalidated.v1`等沿原Envelope（`domain-event-v1.2.schema.json`）。旧版本保留，upcaster显式维护。发布后触发索引更新、通知、依赖失效、对账；读当前事实不必须等派生projection。同步强制检查当前B/policy/evidence，避免Outbox延迟导致绕权/错误closure。

重试：transient 5次默认，2s/4s/8s/16s/32s+jitter（限额与backoff可配置）；deterministic schema/permission/validation conflict不重试，形成blocked/明确返回；依赖暂不可用回入队列；超期/预算耗尽标partial，记录断点和需要人授权/补资料事项；死信状态有admin诊断，不自动丢任务。操作取消、结果超时、重试、恢复都写append-only事件与audit。运行日志/真实tool evidence独立存储，脱敏与访问控制；不得把人输入的命令直接执行在平台主机。运行取消后若外部动作已执行须记录实际状态并复核，而非假装没有发生。

## 5. 可观测性和多人安全

结构化日志、OpenTelemetry trace/metrics（初始可stdout+Prometheus compatible metrics；敏感数据不输出），request/correlation/task/run/commit IDs关联；metrics不暴露项目机密labels。监控：P95/P99 latency、5xx/403（整体）、DB pool/locks/queue age/outbox retry/lease expired、AI tokens/cost/error、索引滞后、blob容量、备份时间/验证、知识债和对账失败；通知只传opaque subject+event。审计append-only记录主体、安全决策、资源版本、动作、结果、timestamp、hash而不是secret/raw内容；访问需Security角色且按project过滤。权限变更、审批、发布、导入、源下载、export、MCP、CI、恢复均有审计。保留期由Owner选择（默认普通运行日志30天、审计和已批准知识按企业policy保留，任何自动删除须授权；不能默认销毁业务证据）。

验收：两用户CAS与approval-race；kill API/Worker mid-transaction/job、outbox replay、expired fence、不同idempotency request conflict、rollback；撤权后打开旧URL、浏览器缓存/历史/导出、MCP resource、source链接、SSE、合同、搜索和助手均无泄漏。编译/前端按钮/静态Schema测试不能代替真实安全验收。
